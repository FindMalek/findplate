---
title: GlitchTip
description: Error tracking with the Sentry SDK.
---

The `glitchtip` module adds the Sentry SDK to `apps/api` (`@sentry/bun`) and to `apps/web` and `apps/dashboard` (`@sentry/nextjs`), pointed at a self-hosted [GlitchTip](https://glitchtip.com). It is off by default.

```bash
findplate create my-app --modules glitchtip
```

## What it adds

Files and folders:

- `apps/web/instrumentation.ts`
- `apps/web/instrumentation-client.ts`
- `apps/dashboard/instrumentation.ts`
- `apps/dashboard/instrumentation-client.ts`

Packages:

- `@sentry/bun`
- `@sentry/nextjs`

## Env keys

```bash
GLITCHTIP_DSN=
NEXT_PUBLIC_GLITCHTIP_DSN=
```

`GLITCHTIP_DSN` is used on the server and `NEXT_PUBLIC_GLITCHTIP_DSN` in the browser, inlined at build. Empty means no events are sent. A compose file is in [self-hosted tools](/docs/self-hosted#glitchtip).

## Remove

Generate without it: leave `glitchtip` out of `--modules`. In a project that already exists, delete the paths above, drop its packages from the `package.json` files, remove its env block and fix what `pnpm check-types` reports.

## Swap

GlitchTip speaks the Sentry protocol, so a Sentry project DSN works in the same two keys.
