The `waitlist` module adds an email form to the hero of `apps/web`, a `waitlist.join` procedure and a Waitlist page in the dashboard where admins see the signups. It is off by default.

```bash
findplate create my-app --modules waitlist
```

## What it adds

Files and folders:

- `packages/db/src/schema/waitlist.ts`
- `packages/db/drizzle/0001_waitlist.sql`
- `packages/db/drizzle/meta/0001_snapshot.json`
- `packages/orpc/src/routers/waitlist.ts`
- `apps/web/components/waitlist-form.tsx`
- `apps/dashboard/app/(app)/waitlist`

## Env keys

None.

Duplicates are ignored. It adds the `waitlist` table through the `0001_waitlist` migration, which is dropped with the module.

## Remove

Run `findplate remove waitlist` in the project, see [add and doctor](/docs/add-doctor#findplate-remove). It deletes the files the module owns, strips its code from shared files and drops its packages, only where you haven't edited them.

If you'd rather do it by hand: for a new project leave `waitlist` out of `--modules`. In a project that already exists, delete the paths above, drop its packages from the `package.json` files, remove its env block and fix what `pnpm check-types` reports.

## Swap

Signups live in your own database. To forward them to a mailing tool, call its api from `packages/orpc/src/routers/waitlist.ts` after the insert, or use the [email](/docs/email) module to send a confirmation.
