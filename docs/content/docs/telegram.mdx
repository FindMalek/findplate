title: Telegram
description: A bot that notifies a chat, with a webhook route and a setup command.
---

The `telegram` module adds `packages/telegram`. It talks to the Bot API directly, no extra dependency. It is off by default.

```bash
findplate create my-app --modules telegram
```

## Set up the bot

1. In Telegram open [@BotFather](https://t.me/BotFather), send `/newbot` and copy the token.
2. Put it in `.env` as `TELEGRAM_BOT_TOKEN` (the cli asks for it when you pick the module).
3. Run the setup command:

```bash
pnpm --filter @acme/telegram telegram:setup "My App Bot" "Alerts from my app"
```

The two optional arguments set the bot name and description. Setup then:

- waits for you to send `/start` to the bot, finds the chat id and writes `TELEGRAM_CHAT_ID` to `.env`
- registers the webhook at `<API_PUBLIC_URL>/telegram/webhook` with a secret, and prints `TELEGRAM_WEBHOOK_SECRET` to add to `.env`

Telegram only calls https urls, so run setup again against your deployed `API_PUBLIC_URL` to register the webhook there.

## Env

```bash
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
TELEGRAM_WEBHOOK_SECRET=
```

Without a token `context.telegram` is `null` and the webhook route answers 404.

## notify

Procedures send through `context.telegram`:

```ts
await context.telegram?.notify("New signup: ada@example.com")
```

The webhook route rejects calls without the secret in `X-Telegram-Bot-Api-Secret-Token`, and answers `/start` with the chat id. Extend `handleWebhook` in `packages/telegram/src/index.ts` for commands of your own.

## Test it

`POST /v1/telegram/test` with `{ "text": "hello" }` as an admin sends a message to the configured chat.

## Remove

Generate without it: leave `telegram` out of `--modules`. In an existing project delete `packages/telegram` and `packages/orpc/src/routers/telegram.ts`, drop `@acme/telegram`, remove the Telegram block from `.env` and fix what `pnpm check-types` reports.

## Swap

`notify()` has the same shape as the [WhatsApp](/docs/whatsapp) one, so you can run both or switch the channel a procedure uses by calling the other one on the context.
