---
title: WhatsApp
description: Notifications over WhatsApp through Kapso template messages.
---

The `whatsapp` module adds `packages/whatsapp`. It sends template messages through [Kapso](https://kapso.ai) with the `@kapso/whatsapp-cloud-api` client. It is off by default.

```bash
findplate create my-app --modules whatsapp
```

## Set up

1. In [Kapso](https://app.kapso.ai) connect a WhatsApp number and create an API key.
2. Fill `.env`:

```bash
KAPSO_API_KEY=
WHATSAPP_PHONE_NUMBER_ID=
WHATSAPP_BUSINESS_ACCOUNT_ID=
WHATSAPP_NOTIFY_TO=+15551234567
WHATSAPP_TEMPLATE_NAME=app_notification
WHATSAPP_TEMPLATE_LANGUAGE=en_US
```

3. Submit the notification template to Meta:

```bash
pnpm --filter @acme/whatsapp whatsapp:setup
```

Meta reviews the template, which can take a few minutes. Messages only go out once it is approved.

Messages you start yourself must use an approved template outside the 24 hour window after the user last wrote, so `notify()` always sends one. The template has a single `{{message}}` variable that carries the text.

## notify

Procedures send through `context.whatsapp`:

```ts
await context.whatsapp?.notify("New signup: ada@example.com")
```

Without `KAPSO_API_KEY` and `WHATSAPP_PHONE_NUMBER_ID` it is `null`.

## Test it

`POST /v1/whatsapp/test` with `{ "text": "hello" }` as an admin sends a message to `WHATSAPP_NOTIFY_TO`.

## Remove

Generate without it: leave `whatsapp` out of `--modules`. In an existing project delete `packages/whatsapp` and `packages/orpc/src/routers/whatsapp.ts`, drop the `@acme/whatsapp` and `@kapso/whatsapp-cloud-api` dependencies, remove the Kapso block from `.env` and fix what `pnpm check-types` reports.

## Swap

`notify()` is one function on the context. To send through Twilio or another provider, keep the `notify` signature and replace the client inside `packages/whatsapp`.
